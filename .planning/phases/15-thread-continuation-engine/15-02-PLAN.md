Create `src/utils/detectThreadContext.js` as a CommonJS module. Follow the same module structure as `src/utils/detectSignals.js` — module-scope constants, named exports at bottom.

**Function 1: classifyThreadStage (THREAD-01)**
Async. Takes `(emailText, jobContext, anthropicKey)`. Calls Claude Haiku (`claude-3-5-haiku-20241022`) with a classification prompt. Returns one of: `'DISCOVERY'`, `'CALL_BOOKING'`, `'POST_CALL'`, `'NEGOTIATION'`, `'CLOSING'`, `'STALLED'`. Returns `'DISCOVERY'` on any error or invalid response (fail open). Only call Haiku when email text is present; return `'DISCOVERY'` immediately if `!emailText`.

Prompt to use:
```
Classify this client email in an ongoing Upwork conversation into ONE of these stages:
DISCOVERY - initial questions, exploring needs
CALL_BOOKING - scheduling or confirming a call
POST_CALL - following up after a call/meeting
NEGOTIATION - discussing price, scope, or terms
CLOSING - contract/hire is imminent
STALLED - client has gone quiet or non-committal

Client email: "${emailText.substring(0, 600)}"
Job context: "${jobContext ? jobContext.substring(0, 300) : 'none'}"

Reply with ONLY one word from the list above.
```

Use Anthropic fetch pattern identical to `checkFollowUpSpecificity` in replies.js — same headers, same error handling, same fail-open return.

**Function 2: measureClientMessageLength (THREAD-08)**
Pure sync. Takes `(bodyText)`. Returns `'SHORT'` (< 30 words), `'MEDIUM'` (30-100 words), `'LONG'` (101+ words). Returns `'MEDIUM'` if bodyText is null/empty. Word count: `bodyText.trim().split(/\s+/).filter(Boolean).length`.

**Function 3: detectStallType (THREAD-05)**
Pure sync. Takes `(emailText, job)` where job is the jobs row (or null). Returns one of the stall_type_enum values: `'THINKING'`, `'PRICING_SILENCE'`, `'CALL_SILENCE'`, `'NO_COMMITMENT'`, `'UNKNOWN'`.

Detection logic (check in this order):
1. If email text matches `/let me think|need (more )?time|think (about|it)|consider(ing)?|not sure yet/i` → `'THINKING'`
2. If `job && job.thread_stage === 'POST_CALL' && job.objection_detected !== 'PRICING'` → `'CALL_SILENCE'`
3. If `job && job.objection_detected === 'PRICING'` → `'PRICING_SILENCE'`
4. If `job && job.thread_client_messages >= 3` and no objection detected → `'NO_COMMITMENT'`
5. Otherwise → `'UNKNOWN'`

**Function 4: parseCcContacts (THREAD-04)**
Pure sync. Takes `(ccRaw)` string. Returns array of `{name: string|null, email: string}` objects. Returns `[]` if ccRaw is null/empty/falsy.

Parse logic: Split on `,`, for each entry trim and match against `/^(.+?)\s*<(.+?)>$/`. If matched: `{name: match[1].replace(/"/g, '').trim(), email: match[2].trim()}`. If not matched, treat entire entry as email: `{name: null, email: entry.trim()}`. Filter out any entries where email is empty.

**Function 5: parseNextStepBlock (THREAD-09)**
Pure sync. Takes `(rawText)` string. Returns object `{our_action, their_action, followup_date, followup_approach}` or `null` if no block found.

Block marker to find (from THREAD_CONTINUATION_V1 prompt template):
```
--- NEXT STEP SUMMARY (Internal) ---
- What we promised: [text]
- What we expect from them: [text]
- Follow-up if no response by: [date text]
- Recommended follow-up approach: [text]
```

Regex to find block:
```javascript
const blockMatch = rawText.match(/---\s*NEXT STEP SUMMARY[^-]*---\s*([\s\S]*?)(?:---|$)/i);
```

Extract each field with a helper:
```javascript
const extract = (label) => {
  const m = block.match(new RegExp(`${label}:\\s*(.+?)(?=\\n-|\\n---|$)`, 'i'));
  return m ? m[1].trim() : null;
};
```

Fields to extract:
- `our_action`: label `What we promised`
- `their_action`: label `What we expect from them`
- `followup_date`: label `Follow-up if no response by` (store as raw string — DB cast handles it)
- `followup_approach`: label `Recommended follow-up approach`

Return null if blockMatch is null. Return the object even if some fields are null.

**Module header comment:** Document each function's input/output and Phase requirement ID.

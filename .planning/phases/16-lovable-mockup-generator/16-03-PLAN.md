Complete rewrite of src/tests/lovable-generator.test.js. Remove all Supertest/app imports. Use direct require of mockupDecision.js. Pure unit tests — no DB, no HTTP, no mocking needed.

Structure the test file with describe blocks:
- 'MOCKUP-01: Decision Matrix — YES classifications'
- 'MOCKUP-01: Decision Matrix — NO classifications'
- 'MOCKUP-01: Decision Matrix — Budget gate'
- 'MOCKUP-01: Decision Matrix — Mixed projects'
- 'MOCKUP-01: Decision Matrix — Edge cases'

Each test calls evaluateMockupDecision with a mock job object (just the relevant fields, no full DB row needed) and asserts on shouldBuild, projectType, alternativeSuggestion.

Use Jest unit project config — these tests do NOT need setup.js or DB connection (same pattern as src/tests/detect-signals.test.js).

**YES cases (shouldBuild === true):**
- { job_heading: 'Build a SaaS dashboard' } → shouldBuild: true, projectType contains 'dashboard' or 'saas'
- { job_description: 'Create a landing page for our startup' } → shouldBuild: true
- { job_heading: 'E-commerce store for cosmetics' } → shouldBuild: true
- { job_description: 'Build a mobile app for iOS and Android' } → shouldBuild: true
- { job_heading: 'Web app for project management' } → shouldBuild: true
- { job_description: 'AI chatbot interface for customer support' } → shouldBuild: true
- { job_description: 'Automation tool with workflow builder UI' } → shouldBuild: true
- { job_heading: 'UI/UX redesign of existing platform' } → shouldBuild: true

**NO cases (shouldBuild === false):**
- { job_heading: 'SEO optimization for e-commerce site' } → shouldBuild: false (service-type NO keyword "SEO" takes priority even when YES keyword "e-commerce" co-occurs — SEO is the primary job type, not UI work)
- { job_description: 'DevOps pipeline setup with Docker' } → shouldBuild: false, alternativeSuggestion matches 'Architecture diagram'
- { job_description: 'Content writing for tech blog' } → shouldBuild: false
- { job_description: 'Data entry for spreadsheets' } → shouldBuild: false
- { job_description: 'Backend API microservice' } → shouldBuild: false

**Budget gate:**
- { amount: '500' } → shouldBuild: false, projectType: 'low_budget'
- { amount: '999' } → shouldBuild: false, projectType: 'low_budget'
- { amount: '1000' } → NOT blocked by budget (amount >= 1000)
- { amount: '0' } → NOT blocked (treated as no budget info)
- { amount: null } → NOT blocked (treated as no budget info)

**Mixed projects (visual component present → YES):**
- { job_description: 'Build REST API and React dashboard' } → shouldBuild: true (has both API and dashboard keywords — visual component overrides)
- { job_description: 'DevOps pipeline with monitoring dashboard' } → shouldBuild: true (visual component overrides)

NOTE: The mixed-project rule (NO + YES → YES) applies ONLY when the YES keyword indicates a genuine visual component (dashboard, UI, app). Service-type NO keywords like SEO, content writing, data entry should NOT be overridden by co-occurring product-type YES keywords (e-commerce, website) because the job's primary nature is non-visual service work.

**Edge cases:**
- null job → shouldBuild: false, no error thrown
- undefined job → shouldBuild: false, no error thrown
- { job_heading: '' } → shouldBuild: false (empty string = no signal)
- job with no relevant fields → shouldBuild: false, projectType: 'unknown'

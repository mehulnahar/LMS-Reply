**CRITICAL FIX (CTA-05 blocker):** The current `proposalGate()` in `src/utils/validateReply.js` only bypasses the pricing pattern-stripping loop when `promptType === 'PROPOSAL_V4' && clientRequestedPricing === true`. This means for EMAIL_REPLY_V2, FOLLOW_UP_V2, and THREAD_CONTINUATION_V1, cost estimates injected by CTA-05 (e.g., "$500-$1,200") will ALWAYS be stripped by the PRICING_PATTERNS loop, even when the client explicitly asked about pricing. The `$X-$Y` dollar amounts and the word "pricing" match PRICING_PATTERNS and get replaced with CALL_REDIRECT.

**The fix:** Change the early-return bypass condition in `proposalGate()` from prompt-type-specific to prompt-type-agnostic:

Read `src/utils/validateReply.js` and locate the `proposalGate` function (around line 87). Change:

```javascript
function proposalGate(text, promptType, clientRequestedPricing = false) {
  // PROPOSAL_V4 with explicit client request: pass through unchanged
  if (promptType === 'PROPOSAL_V4' && clientRequestedPricing === true) {
    return { text, stripped: false };
  }
```

to:

```javascript
function proposalGate(text, promptType, clientRequestedPricing = false) {
  // CTA-05: When client explicitly asked about pricing, pass through unchanged
  // for ANY prompt type — not just PROPOSAL_V4. Cost estimates injected by the
  // prompt pipeline should not be stripped when the client requested them.
  if (clientRequestedPricing === true) {
    return { text, stripped: false };
  }
```

**Also update the JSDoc comment** (around line 74-86) to reflect the new behavior. Change:

```
 * - PROPOSAL_V4 with clientRequestedPricing=true: allowed through unchanged
```

 * - Any prompt type with clientRequestedPricing=true: allowed through unchanged (CTA-05)

**What stays the same:**
- The `removeProofSection()` call for PROPOSAL_V4 without clientRequestedPricing still runs
- The PRICING_PATTERNS loop still runs for all prompt types when `clientRequestedPricing=false`
- The `CALL_REDIRECT` replacement behavior is unchanged for non-client-requested pricing

**Why this is safe:** The `clientRequestedPricing` flag is only set to `true` when `detectPricingLanguage()` finds explicit pricing keywords in the client's email. This is a deliberate, narrow gate: pricing language only passes through when the client brought up the topic first. Unsolicited pricing (Claude hallucinating cost numbers for a non-pricing email) is still stripped.

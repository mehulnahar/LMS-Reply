```javascript
// ──────────────────────────────────────────────────────────
// Step 2.6: Timezone CTA resolution (CTA-01)
// ──────────────────────────────────────────────────────────
let timezoneCTA = '11 AM your time'; // Fallback (CTA-01 edge case)
if (job && (job.city || job.country)) {
  try {
    const location = [job.city, job.country].filter(Boolean).join(', ');
    // Reuse the same Haiku timezone lookup logic as timezone.js (inline, not HTTP call)
    const tzRes = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'x-api-key': anthropicKey,
        'anthropic-version': '2023-06-01',
      },
      body: JSON.stringify({
        model: 'claude-3-5-haiku-20241022',
        max_tokens: 50,
        messages: [{
          role: 'user',
          content: `What is the IANA timezone identifier for ${location}? Reply with ONLY the IANA timezone string, for example: America/New_York or Pacific/Auckland. No explanation.`,
        }],
      }),
    });
    if (tzRes.ok) {
      const tzData = await tzRes.json();
      const ianaTimezone = (tzData.content?.[0]?.text || '').trim();
      if (ianaTimezone) {
        // Validate it's a real IANA timezone before using
        try {
          new Intl.DateTimeFormat('en-US', { timeZone: ianaTimezone }).format(new Date());
          timezoneCTA = formatTimezoneCTA(ianaTimezone);
        } catch {
          // Invalid timezone string from Haiku — use fallback
        }
      }
    }
  } catch (tzErr) {
    // Fail open — use default "11 AM your time" fallback
    console.error('replies: timezone resolution failed:', tzErr.message);
  }
}
```

**WHY before variant parsing:** The variant split happens after this point (Step 6a). By appending the signature before splitting variants, BOTH Variant A and Variant B will include the signature. This is correct because both variants need the signature in the final output.

**IMPORTANT:** The signature is appended to `cleanText` BEFORE the variant split. The variant split (lines ~494-506) splits on `--- VARIANT B ---`. Since the signature is appended at the end, it will appear at the end of Variant B (the last variant). Variant A will NOT have the signature after the split.

Actually, reconsider: the split happens on `--- VARIANT B ---` which divides the text into parts[0] (Variant A) and parts[1] (Variant B). The signature gets appended to the END of the full cleanText, so after splitting it ends up only on Variant B. This is wrong — both variants need the signature.

**REVISED APPROACH:** Append the signature AFTER the variant parsing step instead. Modify the code to apply signature to both variants:

After the variant parsing block (after line 506), add:
```javascript
    // ──────────────────────────────────────────────────────────
    // Step 6.0a: Append signature block (CTA-06)
    // Runs after variant split so both variants get the signature.
    // ──────────────────────────────────────────────────────────
    if (promptType !== 'LOVABLE_MOCKUP_V1') {
      cleanText = appendSignatureBlock(cleanText);
      if (variantA) {
        variantA = appendSignatureBlock(variantA);
      }
      if (variantB) {
        variantB = appendSignatureBlock(variantB);
      }
    }
```

This ensures:
- Single-variant replies (Thread Continuation, Proposal): signature on cleanText
- Dual-variant replies (Reply V2, Follow-Up V2): signature on both variantA and variantB, and on cleanText (which is set to variantA after split)

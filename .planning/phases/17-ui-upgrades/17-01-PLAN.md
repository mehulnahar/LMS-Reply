<task type="auto">
  <name>Task 2: Add PUT /api/replies/:id/variant endpoint for variant selection tracking</name>
  <files>src/routes/replies.js</files>
  <action>
  Add a new endpoint after the existing PUT /:id/copied route (~line 800):

  ```
  PUT /api/replies/:id/variant
  ```

  This endpoint:
  - Requires auth (requireAuth middleware)
  - Accepts `{ variant }` in request body (string: 'A' or 'B')
  - Validates that variant is 'A' or 'B', returns 400 otherwise
  - Updates the `reply_generations` table: `UPDATE reply_generations SET variant_selected = $1 WHERE lead_id = (SELECT job_id FROM replies WHERE id = $2 AND user_id = $3) ORDER BY created_at DESC LIMIT 1`
    - This targets the MOST RECENT reply_generations record for this reply's job, which corresponds to the current generation
    - Alternative simpler approach: just update based on the reply's job_id, most recent record
  - Returns `{ message: "Variant recorded" }` on success
  - Returns 404 if no matching record found

  Also add the corresponding API method in `client/src/api.js`:
  ```
  recordVariantSelected: async (replyId, variant) => {
    const res = await fetch(`${BASE}/replies/${replyId}/variant`, {
      method: 'PUT',
      credentials: 'include',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ variant }),
    });
    if (!res.ok) throw new Error('Failed to record variant');
    return res.json();
  },
  ```

  NOTE: The `variant_selected` column already exists on `reply_generations` (VARCHAR 50, from migration 005). No migration needed.
